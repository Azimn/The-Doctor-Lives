# Articles V3 work wave: native policy to actual task execution

This experimental branch continues the CASCADE candidate from PR #61 without merging it into production. The canonical revised manuscript remains the target for all 34 capacity claims. The complete source and individual Article hashes were verified against the current supplied DOCX during this work. All full-domain Article outcomes remain Unassessable pending their registered studies.

## Behavior added

The existing Doctor `think` method now accepts an optional tuple of currently executable native actions. It applies the existing recurrent and state-policy bridge, then conditions that distribution on the host-authorized alternatives. The default call retains the original ten-action policy and version. Restricted calls record the mask, unconstrained distribution, native selected action, and a named policy-version suffix in the existing `policy_decisions` table. No replacement identity store, neural policy, or cognitive executive is introduced.

The CASCADE host can issue a one-request task grant bound to current state, input digest, and an immutable bounded set of native-action/tool alternatives. Its native policy selects the action, and the host executes the corresponding allowlisted pure checksum method. The renderer is not called for selection. A durable reservation precedes policy execution and prevents replay, including after restart or a failed attempt. State mismatch, altered input, missing authority, invalid action masks, and closed hosts fail before execution. The existing foreground/background operation lock remains in force. No external service, shell command, file-management action, or user-machine service is invoked.

Only an explicit natural-language tool percept enters Doctor experience after computation. Request IDs, payloads, scores, digests, and raw audit records remain engineer-side. Task results and native policy IDs are recorded in existing event and policy tables. Tool authority stays outside the brain.

## Actual-host pilot

The [raw pilot](../../results/cascade/NATIVE_TASK_ACTION_PILOT.json) uses the real canonical Pretorius host with pinned Sensus, Synthetic Ipseity, and Self-Reference Governor, a 128-neuron engineering configuration, and no model inference. Two copies of one existing checkpoint receive a newly presented sample. With both methods available, the native policy selects explore and executes direct SHA-256. With only the other method permitted, it selects comply and executes streaming SHA-256. Both return the expected checksum, both executed actions match the persisted native decision, and neither calls a renderer for action selection.

The changed action follows an availability intervention. It is operational evidence that native decisions can cause actual bounded work, not evidence of learned cognitive superiority, spontaneous goal initiation, or real-world autonomous agency. The simple action-to-tool mapping is authored. Both methods solve the same pure computational task. This pilot is not independent held-out qualification for Articles 14 or 19.
