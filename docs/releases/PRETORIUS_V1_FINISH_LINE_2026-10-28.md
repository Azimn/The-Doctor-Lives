# Pretorius 1.0: finite finish line and truthful completion assessment
Date: 2026-10-28. Status: **proposed bounded release contract**, NOT a claim that v1.0 shipped or a replacement for the governing North Star and accepted evidence rules.

## Executive decision

**Freeze Pretorius 1.0 as ONE reliable offline-capable persistent Laboratory individual, not a completed general human simulation.** One definitive canonical brain, one six-organ functional arrangement, one integrated host, one everyday operator/subject-facing renderer, one authoritative Laboratory, durable autobiographical time and remembered consequences, modest independently recurring life, reviewed source and action authority, reproducible cold installation, backup/restore and 24-hour continuous test. Remote autonomy, arbitrary games/robots, universal psychological fidelity and unbounded research are post-1.0.

No new Pretorius repository, brain, persistent shadow memory, agent or seventh organ. Consolidate dependent PRs, not create parallel mind implementations.

## The assessment as of this date

- **Strong:** production-origin persistence, canonical identity and memory, original recurrent substrate, source-verified Laboratory physics/books/action receipts, source-qualified first-person ingress, opt-in six-organ interfaces, opt-in source-verified learning and Noesis v0.3 concrete action-choice with physical consequences, repeated Actions CI.
- **Functional but experimental:** actual six-organ cycle, endogenous book goal/recollection, Affectus weather/collision models, Sensus conflict handling, durable Ipseity delivery, cross-simulation environment adapter, source-backed book study, context-sensitive work decisions. Pinned real-world tests are meaningful but not equivalent to merged production and long-term reliability.
- **Not finished:** global production renderer and tool capability no-bypass; complete host-owned trust boundaries; all six-organ pathways adopted into the one default runtime; independent unscripted multi-task agency; autonomous wake/resume/commitment scheduling over elapsed real time; full-size neural cross-seed characterization; cold external end-user install and operating transcript; rolling backup/recovery proof; longitudinal stress release suite; independent review, dependency merge, versioned release tag.
- **Specific integration debt:** production `main` is still at the frozen baseline `784cff3...` while four dependent PRs `#89 -> #96 -> #97 -> #98` are open in a stacked research chain. Green CI on #98 is NOT a released program.
- **Legacy research tracker:** `research/articles_34_progress.json` is dated October 16. Its arithmetic mean engineering gate score was ~46%, **zero of the 34 Articles were independently qualified**. This is a *research program* estimate, NOT a percentage measure of a bounded 1.0 release. New October 28 experiments have not been reconciled into its scoring.

### Plain-language readiness estimate
For **the deliberately bounded Laboratory v1.0**, the implementation has **roughly half or slightly more of the necessary functionality** demonstrated somewhere in the research stack, but **substantially less than half of the end-to-end release qualification** has been completed. This is an informed engineering estimate, **not an instrumented metric** or delivery forecast. Do not say "nearly finished" until a clean installation actually operates the integrated mind without development harness orchestration.

## Exactly six release-blocking work packages

### R1. Freeze scope and reconcile dependent code
Agree on this exact 1.0 scope and review the current stacked source graph. In dependency order, reconcile PR #89 architecture with #96 verified ingress/renderer repairs, #97 autobiography-conditioned reading, and #98 Noesis and consequence learning. Preserve every donor/source hash, review finding and negative result. Integrate into one candidate branch then merge reviewed, compatible slices to production; do not create more experimental Pretorius forks. **Pass:** one canonical production runtime and default-or-explicitly enabled functional pathways, one tested code ancestry and no split brain.

### R2. Make the single offline operating runtime real
Ship a start/stop/resume command and stable offline host that runs the same canonical brain, six functional ports and authoritative Laboratory with optional local renderer. Continuous elapsed-world-time scheduling uses UTC/ISO for event ordering and **Swatch Internet Time @beats** as the consistent project-facing clock. A mind-generated bounded wake intention may request host scheduling, and existing concerns/commitments affect opportunities. **Pass:** he can live, be interrupted, wake, and resume an unfinished genuine goal without the test harness feeding a new task.

### R3. Finish the trusted subject/action boundary
Use the repaired source-admission path, a single durable subject-only renderer route, no engineer telemetry in any model tool namespace, explicit authorized action receipts, and protected world truth separate from acquired autobiography. Do not pretend trusted in-process Python is a universal sandbox. **Pass:** adversarial fake-world/source/tool/renderer probes fail in the **actual shipping host**, while 17 source-backed full-text Laboratory books can still be physically read. A privacy/process isolation assessment is required for any untrusted extension.

### R4. Deliver a bounded, consequential daily life
The live integrated mind must observe, choose among real available opportunities, act with host authority, experience cost/benefit through direct first-person receipts, recall and use that experience, pursue at least one self-initiated long-running task, meet/conflict with bodily needs, and recover after interruption. Preserve authored provenance. A 1.0 behavioral transcript must demonstrate this without prewritten post-action dialogue or engineer-predetermined action ordering. **Pass:** an independent repeatable script runs **at least three distinct work/life tasks** and includes one consequence-driven change in a later decision; no impossible world action or fabricated page. Host scheduling is honestly counted as external opportunity, not independent initiative.

### R5. Break it on purpose
Run exact-head non-skipped Lab and Doctor tests, full-size 4,096-neuron smoke, cold-install on a clean runtime outside the checkout, crash between world commit and memory admission, rollback and backup restoration, renderer/model substitution and first-person ingress adversarial tests. Execute a **24-hour elapsed-time soak** with sleep/rest, multiple goals, real work, books and repeated cognitive wakeups. **Pass:** no lost/duplicated world action, broken memory provenance, identity reset, missing authorized experience, leaked engineer state or corrupt recovery. Record explicit negative outcomes; do not repair tests by weakening them.

### R6. Release one visible, usable Pretorius 1.0
Write installation and operator recovery instructions for a non-programmer, human-readable example transcripts and a short architecture/limits report. Tag an immutable release candidate and verify the exact **merged** code, then tag a final 1.0 only after independent signoff. **Pass:** a clean machine can install, create/open Pretorius, see a self-contained offline day in the Laboratory, stop, restore, and resume without cloning donor repos or asking an AI developer to orchestrate steps. Actual continuous operation is observable; mechanisms can remain psychologically limited.

## Things explicitly NOT required for 1.0
Do not block release on full 34-Article graduation, proving consciousness, advanced unrestricted planning, full open-world natural-language action grounding, direct physical robots, Frankenstein Village integration, all proposed research donor organs, general dream evolution, adaptive superhuman strategic inference, external provider process security against a privileged local Python owner, three deferred Lab world-query features, or long-range research predictive advantage over every simple baseline.

These remain honest research backlog, not stealth release blockers. Do not misrepresent a bounded 1.0 as "the complete human simulation."

## Rule for stopping
**No more architecture expansion until R1-R6 are either accepted or a specifically identified blocker is fixed.** Report a simple six-line release register with `not started / implemented / tested / accepted`, exact source commit and exact CI/soak evidence, rather than accumulating partial-prototype percentages. New ideas go in a later-release backlog unless they fix an R1-R6 failure.

**The next highest-leverage task is R1 integration and qualification**. It is more valuable than constructing another isolated cognition demo.
