# Stage 00 research execution: PHASE-style state and selective PersonaForge gate

**Disposition: research mechanics PASS; independent persona-behavior benefit NOT ESTABLISHED; production HOLD.**

Upstream concepts: Tang et al., PHASE-Tree (arXiv:2608.06975); Tong and Zou, PersonaForge (ACL 2026 Findings). This is an **original adaptation of components**, not a full reimplementation or reproduction of published experimental results.

## Source-grounded native integration

GitHub Actions [run 38022209246](https://github.com/Azimn/The-Doctor-Lives/actions/runs/38022209246) successfully completed **9 focused tests**, source-state insulation, and an actual native Pretorius commitment lifecycle test. This used the normal PretoriusBrain and canon-checked store on disposable state.

Tested invariants:
- immutable identity root cannot be addressed by local patches;
- a session field must cite an admitted source reference and cannot be modified retroactively;
- moderate persona requires three distinct, host-registered world-witness episode IDs;
- core persona requires sixteen distinct episodes, six high-significance records, and its cooldown;
- model-written world references and unknown sources fail the research gate (host authenticity remains an unmet external requirement);
- typed conflict signals recommend but do not execute extra inference;
- native renderer obtains only authorized SubjectFrame content, with flat and layered arms containing the same subject-native sentences;
- confidential canaries placed in engineer-only relationship summary and self-model claim fields do not appear in the resulting renderer context;
- the research source adapter does not change the BrainStore.

Native multi-snapshot fixture: create state → open a genuine commitment to review laboratory findings with Henry → capture new snapshot → call native `resolve_commitment` → capture final snapshot. The PHASE-style session layer tracks the new open commitment then removes it on closure, while immutable identity/persona never change and the adapter writes no autobiography. This is exactly the intended state-tracking property, and a stale initial snapshot lacks the new commitment by construction. It does **not** verify completion of any real-world promise.

## Experimental generation

A four-prompt no-API local GGUF generation workflow is tracked in [PHASE_PERSONAFORGE_STAGE00_PROTOCOL.md](../../docs/PHASE_PERSONAFORGE_STAGE00_PROTOCOL.md) and the [blind rubric](../../docs/PHASE_PERSONAFORGE_BLIND_REVIEW_RUBRIC.md). It compares:
- flat native SubjectFrame (equal evidence, original order),
- PHASE-style topical headings around the identical SubjectFrame sentences,
- the hierarchical input plus one additional local conflict-review call on the three critical cases.

The supply chain's first candidate SmolLM2-360M quantizer URL returned 404 in GitHub Actions and generated no outputs. The corrected run uses official Qwen3-0.6B GGUF pinned to SHA256 `da2572f16c06133561ce56accaa822216f2391ef4d37fba427801cd6736417d4` from https://huggingface.co/ggml-org/Qwen3-0.6B-GGUF/blob/main/Qwen3-0.6B-Q4_0.gguf. The source/model change was explicitly recorded **before** any generated response was inspected.

This generation experiment tests response formatting and selective extra inference, NOT PHASE's full long-horizon state evolution and NOT PersonaForge's full measured psychological framework. Its four authored cases cannot establish population-level effects. Until actual generated responses are archived and independently scored, no improvement claim is warranted.
